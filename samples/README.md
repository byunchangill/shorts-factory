# 샘플 데이터

`workspace/`는 깃에 올라가지 않는다. 새 PC에서 앱을 켜면 화면이 전부 비어 있어
무엇도 눌러볼 수 없으므로, 실제 영상과 나레이션을 여기 두고 한 번에 심을 수 있게 했다.

```bash
npm run seed              # 이미 있으면 건드리지 않는다
npm run seed -- --force   # 지우고 다시 만든다
npm run dev               # http://localhost:5173 에서 확인
```

인터넷·API 키·유튜브 쿼터 아무것도 쓰지 않는다. 서버가 안 떠 있으면 seed가
직접 띄웠다가 끝나고 내린다.

## 심어지는 것

`menu-a / 샘플-주방선반 / 1편` 하나가 **음성까지 끝난 상태(voicing)**로 만들어진다.

| 단계 | 내용 |
|---|---|
| 소재 | 영상 4개 첨부 (다운로드가 아니라 "이미 받아둔 파일" 경로) |
| 클립 | ffprobe 분석 + 프레임 47장 추출 |
| 대본 | `narration.srt` → 10씬, 씬마다 클립 구간 지정, 승인까지 완료 |
| 음성 | `narration.mp3`를 자막 구간대로 잘라 씬별 첨부 → timing.json |

이어서 잡 화면에서 **사용 권리 확인 → 최종 조립**을 누르면 1080x1920 영상이 나온다
(확인함: 43초, 자막 번인 + 텍스트 카드 + 공시문구).

## 도구가 없으면

ffmpeg·ffprobe가 없는 PC에서는 클립 분석·프레임·음성을 건너뛰고 **프로젝트·잡·대본까지만**
만든다. 화면 대부분은 그대로 볼 수 있고, seed가 무엇을 건너뛰었는지 알려준다.

## 파일

| 파일 | 내용 |
|---|---|
| `clip1.mp4` | 틱톡 `7596573158967299346` · 720x1280 · 14.4초 |
| `clip2.mp4` | 틱톡 `7586925814772518164` · 720x1280 · 10.9초 |
| `clip3.mp4` | 틱톡 `7611365922317585686` · 576x1024 · 15.0초 |
| `clip4.mp4` | 틱톡 `7585453331401739540` · 720x1280 · 7.3초 |
| `narration.mp3` | 나레이션 29.4초 |
| `narration.srt` | 나레이션 자막 10줄 (대본의 원본) |

영상에는 원본의 외국어 자막·워터마크가 그대로 남아 있다. 일부러 지우지 않았다 —
**자막/워터마크 제거(존 편집) 단계를 실제 소재로 시험해 볼 수 있어야** 하기 때문이다.

## 이 영상들에 대해

개발·테스트용으로만 리포에 둔 남의 영상이다. 이걸로 만든 결과물을 채널에 올리지 않는다.
앱에 조립 전 `rights-confirm` 게이트가 있는 것도 같은 이유다.
