# 샘플 데이터

`workspace/`는 깃에 올라가지 않는다. 새 PC에서 앱을 켜면 화면이 전부 비어 있어
무엇도 눌러볼 수 없으므로, 실제 영상과 나레이션을 여기 두고 한 번에 심을 수 있게 했다.

**화면에서:** 해외영상 짜집기 → 카테고리 선택 → 새 영상 작업 → **샘플 사용하기**

**터미널에서:**

```bash
npm run seed              # 이미 있으면 건드리지 않는다
npm run seed -- --force   # 지우고 다시 만든다
npm run dev               # http://localhost:5173 에서 확인
```

인터넷·API 키·유튜브 쿼터 아무것도 쓰지 않는다. 서버가 안 떠 있으면 seed가
직접 띄웠다가 끝나고 내린다. 화면 버튼과 seed는 **같은 서버 기능**을 쓴다.

## 심어지는 것

`menu-a / 생활용품 / 샘플 - 주방 선반` 작업 하나가 **영상 분석까지만** 만들어진다 (상태: 자막/워터마크 제거).

폴더는 카테고리(생활용품·주방·수납 등)이고, 그 안의 작업 하나가 영상 한 편이다.
샘플도 작업 단위라 같은 카테고리에 몇 편이든 만들 수 있다.

| 단계 | 내용 |
|---|---|
| 소재 | 영상 4개 첨부 (다운로드가 아니라 "이미 받아둔 파일" 경로) |
| 클립 | ffprobe 분석 + 프레임 47장 추출 |

**여기서 멈추는 것이 의도다.** 존 편집 → 1차 제거 → 대본 요청서 → 컷 선택 → 음성 → 조립을
사용자가 직접 밟아야 파이프라인을 처음부터 끝까지 시험할 수 있다.

음성 단계에서는 `narration.mp3`를 씬별로 첨부하거나 타입캐스트로 합성하면 된다.
`narration.srt`는 이 소재에 맞는 나레이션 원본이라 대본을 쓸 때 참고용으로 쓸 수 있다.

### 화면만 빠르게 채우고 싶으면

```bash
npm run seed -- --force --full
```

대본 10씬(자막에서 옮김)과 씬별 음성까지 미리 채워 **음성 단계(voicing)**에서 시작한다.
이어서 **사용 권리 확인 → 최종 조립**을 누르면 1080x1920 영상이 나온다
(확인함: 43초, 자막 번인 + 텍스트 카드 + 공시문구).

## 도구가 없으면

ffmpeg·ffprobe가 없는 PC에서는 클립 분석·프레임 추출이 되지 않는다. 프로젝트·잡·소재 첨부는
그대로 되므로 화면 대부분은 볼 수 있고, seed가 무엇을 건너뛰었는지 알려준다.

## 원본 보존

`samples/`의 파일은 절대 옮기거나 지우지 않는다 — 항상 복사본이 작업 폴더로 들어간다
(첨부 처리가 파일을 rename으로 옮기기 때문에, 원본을 그대로 넘기면 사라진다).
하네스가 매번 해시를 비교해 이 규칙이 깨지지 않았는지 확인한다.

같은 카테고리에 다시 만들어도 작업 번호가 올라가 이전 편을 덮지 않는다.

| `clip4.mp4` | 틱톡 `7585453331401739540` · 720x1280 · 7.3초 |
| `narration.mp3` | 나레이션 29.4초 |
| `narration.srt` | 나레이션 자막 10줄 (대본의 원본) |

영상에는 원본의 외국어 자막·워터마크가 그대로 남아 있다. 일부러 지우지 않았다 —
**자막/워터마크 제거(존 편집) 단계를 실제 소재로 시험해 볼 수 있어야** 하기 때문이다.

## 이 영상들에 대해

개발·테스트용으로만 리포에 둔 남의 영상이다. 이걸로 만든 결과물을 채널에 올리지 않는다.
앱에 조립 전 `rights-confirm` 게이트가 있는 것도 같은 이유다.
