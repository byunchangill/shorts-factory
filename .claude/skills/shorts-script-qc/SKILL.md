# 쇼핑쇼츠 대본 검수

대본이 실제로 영상이 될 수 있는지, 법적으로 문제가 없는지 **계산과 대조로** 판정한다. 인상평은 검수가 아니다.

## 왜 계산해야 하는가

"좀 긴 것 같다"는 판정은 다음 회차에 이어지지 않는다. "230자 → 37초, 상한 30초 초과, 43자 줄여야"는 대본가가 무엇을 얼마나 줄여야 하는지 안다. 측정값이 있어야 개선이 수렴한다.

## 자동 계산 도구

먼저 스크립트를 돌려 기계적으로 셀 수 있는 항목을 처리한다. 손으로 세면 틀린다.

```bash
npx tsx .claude/skills/shorts-script-qc/scripts/check-script.ts <script.json 경로> [--rate 1.33] [--menu menu-b]
```

출력: 메뉴, 씬 수, **총 음절수**, 낭독 배속, 예상 낭독 시간, 교리 실격, 금칙어 적발, 씬별 분포, 단점 씬(menu-b).

🔴 **검사 규칙은 `shared/doctrine.ts` 한 곳에서 온다.** 이 스크립트는 그 함수를 부를 뿐이라
서버가 반영을 거부하는 조건과 **글자 하나까지 같다.** 규칙을 여기에 베껴 적지 않는다 —
예전 `check-script.mjs`가 목표 길이를 20~30초로 오래 들고 있었고, 앱은 그동안 다른 값을 썼다.

**목표 시간은 메뉴마다 다르다** (`TARGET_SEC_BY_MENU`). 스크립트는 경로에서 메뉴를 유추하고,
경로로 알 수 없으면 `--menu`로 지정한다.

**분량은 글자수가 아니라 한글 음절수다.** 공백·기호·영문·숫자를 빼고 센다 —
글자로 세면 공백까지 예산에 들어가 같은 대본이 20% 짧게 판정된다.

스크립트가 잡지 못하는 것(훅 강도, 소재 정합성, 구성 흐름)은 아래 절차로 직접 판단한다.

## 배점 (100점, 85점 이상 통과)

### 해외영상 짜집기 (menu-a) — 교리 v3.3

**실격이 하나라도 있으면 점수를 매기지 않는다.** 스크립트가 전수 검사하므로 먼저 돌린다.
실격이 없을 때에만 아래로 채점한다.

| 항목 | 배점 | 0점 조건 |
|---|---|---|
| 훅 강도 | 25 | ① 훅이 8종 중 어디에도 안 들어감 / 제품이 새어 나감 |
| ② 손실의 무게 | 25 | 손실이 있긴 한데 남 얘기 같다. 금전 손실이 가능한데 시간·신체로 갔다 |
| 선행 구간 배분 | 15 | 표 안에는 들지만 ①이 3초를 넘겨 손실이 눌렸다 |
| 소재 정합성 | 20 | 존재하지 않는 clipId, 구간이 클립 길이 초과 |
| 문체 | 15 | 어미는 갈렸지만 문어투가 남았다 (「상부장」·「절어서」) |

🔴 **「나레이션/자막 분리」 배점은 없어졌다** (2026-08-21). v3.3은 **음성 = 자막**이라
같은 문장이 정답이고, 다르면 점수가 아니라 **즉시 반려**다. 예전 배점표는 정확히 반대로
10점을 줬다 — 옛 판정을 기억에 두고 채점하지 말 것.

### 제품정보리뷰 (menu-b)

| 항목 | 배점 | 0점 조건 |
|---|---|---|
| 낭독 시간 | 20 | 메뉴 목표 범위 밖 (배속 반영 후) — 18~26초 |
| 훅 강도 | 20 | 첫 씬이 설명형 |
| 소재 정합성 | 20 | 존재하지 않는 clipId, 구간이 클립 길이 초과 |
| 나레이션/자막 분리 | 10 | 동일 문장 사용 |
| 지침 준수 | 15 | 위반 항목당 -5 |
| CTA | 10 | 마지막 씬에 구매 유도 없음 |
| 구성 완결성 | 5 | 씬 흐름이 끊김 |

## 차단 항목 — 점수와 무관하게 즉시 반려

법적 문제이거나 채널 제재로 이어지는 항목이다. 90점이어도 하나라도 걸리면 반려한다.

### 교리 실격 (해외영상 짜집기 전용)

`check-script.ts`가 내는 실격은 **전부 즉시 반려**다. 서버도 같은 검사로 반영을 거부하므로
여기서 통과시켜도 앱에서 되돌아온다. 대표적인 것 —
음성≠자막 / 2인칭 질문형 / 스펙 단위·아라비아 숫자 / 여성 화자 호칭 / `block` 표시 누락 /
선행 구간 이탈 / 인접 씬 같은 어미 / `~더라고요` 2회 미만.

### 단점 씬 누락 (제품정보리뷰 전용)

`isDownside: true` 씬이 없으면 반려한다. 있어도 **내용을 읽고** 판정한다 — 스크립트는 표시만 볼 수 있다.

| 반려 | 왜 |
|---|---|
| 표시된 씬 없음 | 광고 붙여넣기와 구분되지 않는다 |
| 장점을 단점처럼 씀 ("너무 잘 흡수돼서 금방 써요") | 단점을 말하는 척하는 게 더 나쁘다 |
| 제품 정보에 근거 없는 단점 | `product.json`의 cautions·specs와 대조한다. 없으면 지어낸 것이다 |
| 뒤에 덮는 문장 ("근데 이 가격이면 감수할 만하죠") | 단점은 단점으로 끝나야 신뢰가 된다 |

### 과장·단정 표현

```
무조건, 100%, 완벽, 기적, 완치, 즉시 해결, 부작용 없음,
최저가 보장, 유일한, 세계 최초, 반드시 효과
```

효능은 "~에 도움이 될 수 있다" 수준으로만. 건강기능식품·의료기기는 특히 엄격하게 본다.

### 원본 문장 재사용

해외 영상의 자막·나레이션을 번역해 옮긴 문장이 있으면 반려한다. 구조와 페이싱 참고는 허용, 문장 복제는 금지. 판단이 애매하면 대본가에게 출처를 묻는다.

### 근거 없는 사양·수치

`product.json`이나 첨부 자료에 없는 숫자(용량, 출력, 성능)가 대본에 있으면 반려한다. 지어낸 스펙은 허위광고가 된다.

## 소재 정합성 대조 (메뉴 A)

가장 자주 터지는 항목이다. 존재 확인이 아니라 **교차 대조**를 해야 한다.

1. 요청서 `request.md`의 "소재 현황" 표에서 실제 클립 ID 목록과 각 길이를 읽는다
2. 대본의 모든 `clipRef.clipId`가 그 목록에 있는지 확인 — 없으면 0점
3. `suggestedSegment.in/out`이 해당 클립 길이 안에 들어가는지 확인 — `out > 클립 길이`면 0점
4. `in < out`인지 확인

이 검증을 건너뛰면 조립 단계에서 "클립 없음" 에러로 무너진다.

## 훅 강도 판정

첫 씬이 아래 중 하나에 해당하면 통과다.

| 유형 | 예 |
|---|---|
| 가격충격 | "3만원짜리가 30만원 제품을 이겼습니다" |
| 질문 | "이 가격에 이게 된다고요?" |
| 반전 | "비싼 걸 샀는데 후회했습니다" |
| 문제상황 | "매번 이것 때문에 짜증나셨죠" |
| 실사용시연 | (즉시 테스트 장면 + 결과 예고) |

설명형("오늘은 무선청소기를 소개합니다")은 감점이다. 시청자가 3초 안에 멈출 이유가 없다.

## 반려 사유 작성 원칙

대본을 대신 써주지 않는다. 무엇이 왜 문제인지와 방향만 제시한다.

- 나쁜 예: "s01을 '3만원인데 이게 되네요'로 바꾸세요" → 검수자가 대본을 쓰기 시작하면 검수 관점을 잃는다
- 좋은 예: "s01이 설명형입니다. 리서치에서 이 카테고리 상위 영상 7/10이 가격충격형으로 시작했습니다. 가격 각도로 교체를 권합니다"

## 검증 불가 처리

대조 기준이 없을 때(요청서 없음, 소재 현황 없음) 임의로 통과시키지 않는다. 해당 항목을 "검증 불가"로 표시하고 그 배점을 제외한 뒤 나머지를 100점 만점으로 환산한다. 환산했다는 사실을 판정에 명시한다.
