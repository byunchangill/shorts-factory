# 요청서 처리 (answer-job)

인자로 요청서 폴더 경로를 받는다. 예:
`/answer-job workspace/menu-a/무선청소기/jobs/20260810-001-1편/requests/p03-script`

요청서는 어떤 AI로도 처리할 수 있는 자기완결 문서다. 이 스킬은 그중 **파일 접근이 가능한 경로**(Claude Code)를 담당한다. 웹앱에서 API 자동 실행이나 복사·붙여넣기로 처리할 수도 있으며, 세 방식 모두 같은 `result/` 규약을 따른다.

## 처리 순서

1. **요청서 읽기**: `{요청서폴더}/request.md`를 Read로 읽는다. 목적·지침·제품정보·소재현황·산출물 명세·검증 규칙이 모두 들어 있다.
2. **컨텍스트 확인**: request.md가 참조하는 파일(제품 첨부파일, 클립 프레임 이미지 등)을 Read로 확인한다. 프레임 이미지는 반드시 열어서 실제 화면을 본 뒤 씬-클립 매칭을 결정한다.
3. **산출물 작성**: request.md의 "산출물 명세" 섹션에 적힌 파일명과 JSON 스키마를 정확히 지켜 `{요청서폴더}/result/`에 작성한다.
   - JSON 파일은 스키마 필드명을 정확히 사용 (서버가 zod로 검증하며, 불일치 시 반려됨)
   - "검증 규칙" 섹션의 조건(낭독 시간, 금칙어 등)을 스스로 점검한 후 저장
4. **완료 마커**: 모든 산출물 작성이 끝난 뒤 **마지막에** `{요청서폴더}/result/.done` 빈 파일을 생성한다. 서버가 이 파일을 감지해 자동으로 결과를 반영한다.

## 금지 사항

- `result/` 밖의 어떤 파일도 수정하지 않는다 (job.json, packet.json, 지침 파일 등은 서버/사용자 소유)
- 산출물에 요청서에 없는 파일을 추가하지 않는다 (보조 설명이 필요하면 `result/notes.md`만 허용)
- 원본 영상의 문장을 그대로 옮기지 않는다 — 구조와 페이싱만 참고
- 과장 표현("무조건", "100%", "기적", "완치") 사용 금지

## 대본 작성 요령 (kind: script / revision)

- **분량은 메뉴마다 다르다.** 여기에 숫자를 적어두지 않는다 — 요청서의 "검증 규칙"에
  그 잡의 실제 상한·권장이 계산돼 나오므로 **요청서 값을 그대로 따른다**
  (출처는 `shared/constants.ts`의 `TARGET_SEC_BY_MENU`·`charBudget`. 제품정보리뷰가 해외영상 짜집기보다 짧다)
- 씬 수는 글자 예산에서 역산한다. 씬당 35~45자를 유지하되, **씬 수 × 씬당 글자가 권장 분량을 넘지 않는 선**까지만 늘린다.
  짧은 메뉴에서 씬을 늘리면 씬당 글자가 문장이 안 되는 지점이 먼저 온다. 반전은 1개에 집중한다
- 첫 씬은 3초 훅 (질문/반전/가격 충격 중 택1)
- 나레이션은 타입캐스트 TTS가 그대로 읽으므로, 읽기 어려운 기호·영문 약어는 한글로 풀어 쓴다
- menu-a: 각 씬의 `clipRef.clipId`는 소재 현황 표의 실제 클립 ID만 사용, `suggestedSegment`는 클립 길이 안에서 지정
- menu-b: `clipRef` 대신 `imagePrompt` 사용, 고유 포맷의 `sceneTemplate.imageStylePrompt`를 접두어로 일관 적용
- 마지막 씬에 CTA 1문장 (쿠팡 링크 유도)
