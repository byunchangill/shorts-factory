# 쇼핑쇼츠 바이럴 기획

제품을 설명하는 게 아니라 **조회수 구조를 설계**한다. 기능보다 감정이, 정보보다 궁금증이, 설명보다 반응이 먼저다.

## 왜 구조가 먼저인가

첨부 실측 데이터 69편을 보면, 같은 수준의 제품인데 조회수가 5만과 859만으로 갈린다. 차이는 제품이 아니라 **어떤 구조로 포장했는가**다. "이유궁금증형"은 평균 5만, "가격·효용 충돌형"은 평균 226만이다. 그래서 제목을 쓰기 전에 구조부터 정한다.

구조별 실측 성과와 제목 공식: `references/structure-library.md`
검증된 제목 69편 전체: `references/proven-titles.md`
말투·리듬 학습용 실제 원고: `references/tone-guide.md`

## 최우선 원칙 — 먼저 조사한다

제품을 받으면 대본부터 쓰지 않는다. 반드시 먼저 조사한다.

- 커뮤니티 반응, 댓글 반응
- 브랜드 스토리 (탄생 서사, 위기, 우연)
- 패키징이나 제품의 특이한 요소
- 비슷한 제품과 다른 점
- 사람들이 이 제품을 좋아하는 이유
- 공감할 만한 이야기

브랜드 스토리가 약하면 → 지금 커뮤니티에서 언급되는 가십·화제·공감 요소로 대체한다.

조사 수단: WebSearch, 그리고 서버가 떠 있으면 유튜브 리서치 API
```bash
curl -s "http://localhost:4310/api/youtube/search?query=<제품명>&shortsOnly=true&order=viewCount&days=90"
```

## 단계별 진행 — 매 단계 사용자 선택을 받는다

한 번에 끝까지 가지 않는다. 각 단계마다 결과를 보여주고 번호를 고르게 한다.

### 1단계 — 제품 분석 + 구조 선택

분석할 것:
- 제품 특징 (상식과 어긋나는 지점이 무엇인가)
- 타겟 심리
- 이 제품에 맞는 조회수 구조 **TOP 5**

구조는 이름만 나열하지 말고 **어떤 심리를 자극하는지** 함께 쓴다.

```
"평생 쓸 수 있는 OO"     → 손해 회피 + 가격 대비 효용 충돌 (실측 평균 226만)
"OO들이 환장하는 OO"      → 특정 집단 자기화 (실측 평균 84만)
```

### 2단계 — 제목 5개

선정한 구조로 제목을 만든다. 각 제목마다:
- 사용한 구조
- 클릭 심리
- 저장 심리
- 댓글 유도 포인트
- 조회수 가능성

5개가 서로 다른 각도여야 한다. 비슷하면 1개를 쓴 것과 같다.
→ **사용자에게 번호 선택 요청**

### 3단계 — 썸네일 문구 5개

선택된 제목 기준. 각 문구마다: 왜 강한가 / 어떤 감정을 자극하는가 / 왜 저장될 가능성이 있는가
→ **번호 선택 요청**

### 4단계 — 초반 3초 도입부 5개

조건:
- 첫 문장부터 이질감
- 바로 본론
- 인사로 시작하지 않는다
- 유지율 최우선

실측 데이터의 공통 패턴: **0초에 제목을 그대로 반복해 주제를 고정**하고, 곧바로 상식과 다른 문제를 던진다.

각 도입부마다: 유지율 포인트 / 패턴 인터럽트 요소 / 왜 계속 보게 되는가
→ **번호 선택 요청**

### 5단계 — 최종 원고 2개

조건:
- 짧은 문장, 빠른 리듬
- 감탄 반복
- 계속되는 반전
- 정보와 감정을 함께
- **광고처럼 느껴지면 실패**

반드시 포함: 저장 포인트 / 댓글 포인트 / 공유 포인트 / 구매욕 포인트

## 분량

| 기준 | 글자 수 | 근거 |
|---|---|---|
| 하한 | 150자 (30초) | 너무 짧으면 반전을 넣을 자리가 없다 |
| **권장** | **230~280자 (46~56초)** | **실측 69편 중앙값이 287자(약 57초)** |
| 상한 | 290자 (58초) | 쇼츠 상한 |

사용자 지침의 "30~50초"보다 실측이 길다. 반전을 2번 이상 넣으려면 45초 이상이 필요하다. 30~50초를 원하면 반전 1개로 압축한다.

## 말투

친구가 신기한 걸 발견하고 흥분해서 설명하는 느낌. 반말, 커뮤니티 말투, 리액션 섞인 설명체.

**감탄**: 미친 / 개쩌는 / 변태같은 / 환장하는 / 레전드 / 끝판왕 / 이건 못참지
**연결**: 아니 근데 / 심지어 / 여기서 끝이 아님 / 근데 더 미친건 / 알고보니 / 근데 이유가 있음
**마무리**: 이건 좀 탐나는데? / 저장해둬야겠다 / 이건 인정 / 이래서 난리났네

**문장 구조**: 짧은 문장 → 감탄 → 반전 → 리액션 → 추가 정보

## 쓰지 않는 표현

```
해당 제품은 / 효율적입니다 / 장점은 / 사용자 입장에서
추천드립니다 / 결론적으로 / 요약하자면
```
AI가 정리한 글, 블로그 리뷰, 홈쇼핑 말투, 스펙 나열 — 전부 실패다.

## 감정 표현과 허위 과장의 구분 (중요)

이 프로젝트의 콘텐츠 규칙은 과장을 금지한다. 하지만 **감정 표현과 효능 과장은 다르다.**

| 허용 (감정 강도) | 금지 (허위·효능 단정) |
|---|---|
| 미친 / 환장하는 / 개쩌는 / 레전드 | 무조건 / 100% / 기적 / 완치 |
| 끝판왕 / 1황 / 선넘은 | 부작용 없음 / 반드시 효과 |
| "이건 못참지" | "이거 쓰면 무조건 낫습니다" |

기준: **말투의 온도는 높여도 되지만, 제품이 하지 못하는 일을 한다고 말하면 안 된다.** 근거 없는 수치·사양도 마찬가지다.

## 최종 산출

사용자가 제목·썸네일·도입부·원고를 모두 고르면 하나로 합쳐 제공한다.

```
최종 제목 / 최종 썸네일 문구 / 최종 도입부 / 최종 원고
```

그 다음 분석을 붙인다: 제목 구조 / 썸네일 구조 / 초반 3초 유지율 / 감정 흐름 / 저장·댓글·공유 유도 요소 / 구매욕 발생 지점 / 건드린 인간 심리 / 조회수가 나올 가능성의 근거.

## 요청서 연동

요청서 경로를 받았다면 최종 원고를 `result/script.json` 스키마로 변환해 쓰고 `result/.done`을 만든다. 씬 분할은 문장 리듬을 기준으로 하되, 메뉴 A는 소재 현황의 실제 클립 ID만 `clipRef`에 쓴다.
