# 썰형 쇼핑 대본 교리 v1

출처가 둘이고, **부딪히는 자리를 정리해서 합친 것**이 이 문서다.

- **썰형 포맷** — AI 썰 쇼핑 숏폼 가이드 상·하편 (2026-08-23 이식). 반말 커뮤니티체,
  정보를 가장한 유래·비하인드, 간접 화법, 첫 3초 호기심 후킹, 짤방 연출
- **이 채널의 기존 제품정보리뷰 규칙** — 단점 씬 1개 필수, 비평·정보 관점,
  허위·효능 과장 금지, 18~26초

둘이 충돌한 네 자리는 아래 「합치면서 갈린 것」에 그대로 적어 뒀다. **먼저 읽어야 할 절이다** —
썰형을 곧이곧대로 따르면 이 채널이 이미 세워둔 방어선을 무너뜨린다.

---

## 한 줄 정의

커뮤니티 익명 '썰' 형식을 빌려, 시청자가 **광고라는 거부감 없이 정보를 소비하다가**
제품을 발견하게 만드는 쇼핑 숏폼.

표면은 재밌는 이야기·유용한 지식이고, 본질은 스토리텔링형 제품 소개다.
"이거 좋아요"라고 말하는 순간 시청자는 3초 만에 넘긴다.

---

## 합치면서 갈린 것 (먼저 읽는다)

### 1. 지어내도 되는 것과 안 되는 것을 가른다 🔴

썰형은 "커뮤니티에서 봤는데" 형식을 쓴다. 그러면 **어디까지 각색해도 되나**가 곧바로 문제가 된다.
경계는 하나다.

| | 각색 | 근거 |
|---|---|---|
| **정황** — 누가·언제·어디서·왜 | ✅ 허용 | 익명 썰은 원래 정황이 흐리다 |
| **제품에 관한 사실** — 효능·사양·가격·성분·수상 | ❌ 금지 | 제품 자료에 있는 값만 쓴다 |

간접 화법을 **근거 없는 효능 주장의 방패로 쓰지 않는다.** "~라고 하더라"를 붙여도
"이거 바르면 낫는다"는 여전히 효능 주장이다. 화법이 바뀌었을 뿐 주장은 그대로다.

```
❌ 이거 쓰니까 무릎 통증 싹 사라졌다고 다들 그러더라
✅ 무릎에 힘 덜 들어간다는 후기가 유독 많더라
```

### 2. 단점 씬은 썰형에서도 필수다

썰형 가이드에는 단점 이야기가 없다. 하지만 이 채널은 **단점 씬 1개가 코드로 강제된다** —
씬에 `"isDownside": true`가 없으면 요청서 반영이 거부된다. 형식 요건이 아니라 광고와
리뷰를 가르는 자리라 뺄 수 없다.

썰체와도 잘 맞는다. 간접 화법이 오히려 단점을 자연스럽게 만든다.

```
✅ 근데 이거 지문 개잘 묻는다고 다들 한 마디씩 하더라
✅ 물걸레는 안 된다 함. 이건 감안하고 사야 됨
```

**단점 뒤에 그걸 덮는 마무리를 붙이지 않는다.** 단점은 단점으로 끝내야 신뢰가 생긴다.

### 3. 길이는 18~26초다 (썰형 가이드의 "30초"가 아니라)

가이드는 30초라고 말하지만, 이 앱의 목표는 **18~26초 (권장 22초)**이고 그 숫자는
`TARGET_SEC_BY_MENU`가 단일 출처다. 지침과 앱이 다른 숫자를 말하면 요청서 하나에
모순된 지시가 실린다. **26초를 넘기지 않는다.**

### 4. 감정 형용사는 쓰되, 효능 과장은 아니다

해외영상 짜집기(temcasting-v33)는 `미친`·`역대급`·`끝판왕` 같은 평가 형용사를 실격으로
막는다. **이 메뉴는 다르다** — 커뮤니티체의 온도가 곧 포맷이라 감정 표현은 허용한다.

막는 것은 형용사가 아니라 **검증 불가능한 주장**이다.

```
✅ 미친 / 환장하는 / 레전드 / 개꿀 / 이건 좀 소름       (말투의 온도)
❌ 무조건 / 100% / 기적 / 완치 / 부작용 없음 / 이거면 끝  (효능·확정 주장)
```

## 말투 — 반말 커뮤니티체

존댓말은 그 순간 '광고' 경계심을 켠다. 커뮤니티 베스트 글을 읽는 느낌으로 쓴다.

- 어미: `~했음` `~임` `~다고 함` `~더라` `~하더라` `~됨` `~는 거임`
- 문장이 짧아진다. 짧아야 18~26초에 정보가 들어간다
- **씬 하나에 문장 하나.** 음성 합성이 씬 단위로 도는데 두 문장을 넣으면 뒷문장이
  잘려 나간다 — 소리가 안 나는 게 아니라 짧게 끝나서 조용히 지나간다
- 어미를 연달아 반복하지 않는다. `~임`이 세 씬 연속이면 그게 AI 티다

```
❌ 이 제품은 스테인리스 재질로 제작되어 내구성이 뛰어납니다
✅ 근데 이게 원래 주방용으로 나온 게 아니었음
```

## 구조 — 씬 4~5개

| 씬 | 역할 | 분량 |
|---|---|---|
| ① 훅 | 0~3초. **호기심**을 던진다. 제품·브랜드 언급 0 | 짧게 |
| ② 썰 | 유래·비하인드·남의 경험. 아직 제품은 안 나온다 | 가장 길다 |
| ③ 발견 | "근데 알고 보니 이게…" — 제품이 여기서 드러난다 | |
| ④ 단점 | `isDownside: true`. 간접 화법으로 | |
| ⑤ 클로징 | 저장·공유를 부른다 | 한 문장 |

**반전은 1개에 집중한다.** 짧은 분량에 2개를 넣으면 둘 다 약해진다.
제품은 ③ 전에 확정되지 않게 한다 — 훅에서 제품명이 나오면 그 순간 광고가 된다.

### ① 훅은 공감이 아니라 호기심이다

썰형에서는 공감형보다 호기심형 후킹이 훨씬 강하게 먹힌다.
"뭔데? 궁금해"가 안 나오면 아무리 좋은 제품이어도 끝까지 안 본다.

| 유형 | 예 |
|---|---|
| 뜻밖의 출처 | 이거 원래 병원에서 쓰던 거임 |
| 제3자 인정 | 제조사도 예상 못 한 쓰임새가 있음 |
| 금지·경고 | 이거 이렇게 쓰면 안 된다고 함 |
| 숫자 없는 규모 | 재고가 하루 만에 털린 이유가 있었음 |

**2인칭 질문형으로 열지 않는다.** `아직도 힘들게 닦으세요?` 형태는 이 채널 발행 원장에서
계속시청 12.4%로 최하위였다. 궁금하게 만드는 것과 물어보는 것은 다르다.

### ② 몸통은 '정보'여야 한다

단순 제품 소개나 사용 장면 나열은 **재사용 콘텐츠로 분류될 수 있다.**
아래 6가지 중 **최소 2가지**를 반드시 넣는다. 앞의 둘이 썰형의 주력이다.

- **유래·비하인드** — 원래 뭘 위해 만들어졌나, 왜 이렇게 생겼나
- **기발한 쓰임새** — 뻔한 용도 말고 무릎을 탁 치게 하는 활용법
- **실사용자 반응** — 커뮤니티·리뷰에서 실제로 나온 평가
- **비교 평가** — 대체품·상위 모델과 무엇이 다른가
- **가격 대비 판단** — 이 값을 낼 만한가
- **단점·주의점** — ④가 이걸 맡는다 (이건 그냥 세지 않는다, 별도 필수다)

핵심은 **내가 알려주는 게 아니라 "사람들이 그렇게 한다더라"**로 푸는 것이다.
가르치는 순간 광고가 되고, 전하는 순간 정보가 된다.

### ⑤ 클로징은 저장·공유를 부른다

알고리즘이 보는 건 좋아요가 아니라 **저장·공유·완주율**이다.

```
✅ 이건 저장해뒀다가 이사할 때 꺼내 보면 됨
✅ 주방에 이거 있는 사람 태그하셈
❌ 지금 바로 확인해보세요 / 링크는 아래에 있습니다  (광고 어법)
❌ 여러분은 어떠신가요?                              (2인칭 질문형)
```

## 분량 (배속 1.6 기준)

**한글 음절로 센다. 글자가 아니다** — 공백·문장부호는 낭독 시간에 안 들어가는데
글자로 세면 예산에 넣어 같은 대본이 20% 짧게 판정된다.

| 러닝타임 | 음절 |
|---|---|
| 18초 (하한) | 약 118음절 |
| 22초 (기본) | 약 144음절 |
| 26초 (상한) | 약 169음절 |

**169음절을 넘지 않는다**. 씬 하나는 25~40음절이 적당하다.
배속을 바꾸면 이 표도 같이 바뀐다 — 요청서에 적힌 숫자가 있으면 그쪽이 우선이다.

---

## 연출 (대본이 만들어 주는 것)

썰형은 **제품 연출컷 대신 흐름에 맞는 짤방·스톡 영상**을 쓴다. 대본이 그 재료를 지정한다.

- 씬마다 `imagePrompt`에 **그 문장을 받아내는 그림**을 적는다.
  제품 사진만 반복하면 썰의 리듬이 죽는다
- 웃긴·황당한 대목에는 짤방이 붙는다. 자료실(짤방·효과음)에 있는 것을 쓸 거면
  `imagePrompt` 대신 어떤 느낌의 짤인지 한 줄로 적어 둔다 — 편집에서 골라 넣는다
- 자막은 1~2초 단위로 빠르게 전환된다. 그래서 **씬 하나에 문장 하나**가 여기서도 맞다

## 금지

- 허위·효능 과장: `무조건` `100%` `기적` `완치` `부작용 없음`
- 효능은 "~에 도움이 될 수 있다" 수준으로 완화한다
- **제품 자료에 없는 수치·사양을 지어내지 않는다** (위 「1. 지어내도 되는 것」 참고)
- 2인칭 질문형 훅·CTA
- 광고 어법: `지금 바로` `놓치지 마세요` `이런 분들께 추천` `필수템`
- 원본 영상 문장 재사용 — 구조·페이싱만 참고한다

---

## 자체 검산 (쓰고 나서 반드시)

1. 총 음절이 118~169인가. 씬마다 25~40음절인가
2. 씬 하나에 문장이 하나인가
3. 훅에 제품·브랜드가 안 나오는가. 2인칭 질문형이 아닌가
4. `isDownside: true` 씬이 있는가. 그 씬이 **실제로** 단점을 말하는가
5. 몸통에 정보 관점이 2가지 이상 들어갔는가
6. 어미가 연달아 반복되지 않는가
7. 제품에 관한 사실 중 **제품 자료에 없는 것**을 적지 않았는가

하나라도 걸리면 고쳐서 다시 검산한다.

## 요청서로 실행할 때

이 지침이 요청서에 통째로 실려 올 때가 있다. 그때는:

- 쓰기는 그 요청서 폴더의 `result/`에만 한다. `job.json`·`packet.json` 같은 상태 파일은
  서버 전용이라 **건너뛴다**
- 산출물 파일명·스키마는 요청서의 「산출물 명세」를 정확히 따른다
- 다 쓴 뒤 마지막에 `result/.done` 빈 파일을 만든다 — 서버가 그걸 보고 검증·반영한다
